# AGENTS.md    
  
Инструкции для AI-агентов, работающих с репозиторием RP2040_audio_dsp.    
  
## Что это за проект    
  
Моноканальный DSP-тракт НЧ аудио радиостанции на RP2040 (Raspberry Pi Pico).    
АЦП с оверсэмплингом -> децимация /16 -> полосовой FIR -> CW-биквады ->    
автонотч -> шумоподавление -> АРУ -> fan-out на PWM (GPIO) и USB Audio    
(UAC-микрофон, всегда включён).    
  
Управление функциями — по GPIO (замыкание пина на GND), через Serial CLI    
и Kenwood-подобные CAT-команды (по `;`).    
  
Проект портирован из ru0aog/RP2040_radiomodem и ru0aog/RP2040_receiver —    
при сомнениях сверяться с оригиналами (см. раздел «Происхождение кода» в README.md).    
  
## Архитектура — что где лежит    
  
| Файл                    | Назначение                                              |    
|-------------------------|---------------------------------------------------------|    
| `src/af_config.h`       | ВСЕ константы: Fs, пины, параметры фильтров. Менять здесь |    
| `src/af_capture.cpp`    | ADC 250 ksps + 2 DMA-канала chain_to, IRQ на Core 0     |    
| `src/af_dsp.cpp`        | DC-EMA -> CIC/2 -> HB/2 -> HB/2 -> HB/2 (15.625 ksps) -> ПФ -> CW -> NT -> NR -> АРУ -> 2 очереди |    
| `src/af_pwm.cpp`        | PWM ~125 кГц + DMA pacing 15.625 ksps, 4 duty-буфера, отложенный старт (Core 0) |    
| `src/af_usb.cpp`        | UAC-микрофон 44100/16, всегда включён (Core 0)          |    
| `src/af_cli.cpp`        | Serial-команды + Kenwood CAT по `;` (Core 0)            |    
| `src/af_gpio_ctl.cpp`   | Управление NT/NR/полосой по GPIO, дебаунс (Core 0)      |    
| `RP2040_audio_dsp.cpp`  | setup/loop (Core 0), setup1/loop1 (Core 1)              |    
  
## Жёсткие правила — не нарушать    
  
1. **Разделение по ядрам.** Core 1: только `af_dsp_poll` — весь DSP.    
   Core 0: `af_capture` (DMA_IRQ_0), `af_pwm_poll`, `af_usb_poll`,    
   `af_cli_poll`, `af_gpio_ctl_poll`. `af_capture_start()` вызывается    
   из `setup()` на Core 0 — IRQ захвата живёт на Core 0, чтобы не    
   конкурировать с DSP за Core 1.    
  
2. **Синхронизация запуска ядер.** Core 1 в `setup1()` ждёт флаг    
   `core0_ready` (таймаут 10 с) и только потом входит в `loop1()`.    
   `core0_ready = true` взводится ПОСЛЕДНИМ в `setup()` — после всей    
   инициализации Core 0, с `__dmb()` перед записью.    
  
3. **КРИТИЧНО: порядок USB-инициализации** (корень «USB-устройство не    
   опознано» / зависания). `af_usb_init()` вызывается ПЕРВЫМ в `setup()`,    
   ДО `Serial.begin()` — внутри `usb_out.begin()` маунтится TinyUSB-стек,    
   CDC регистрируется последним. Дескрипторы не должны меняться в окне    
   энумерации. Из `af_usb_init()` НЕ печатать в Serial и не делать    
   detach/attach.    
  
4. **Только целочисленная арифметика в горячем пути.** Q15/int64.    
   Никаких float/double в `af_dsp_poll`, ISR, `*_push`-функциях.    
   Деления int64 в NT/NR заменены нормировкой по старшему биту    
   (`__builtin_clzll` + сдвиг) — не возвращать `/` в горячий цикл.    
   Float допустим только в редких операциях (пересчёт коэффициентов    
   `af_fir_init`, `af_dsp_set_band`, инициализация).    
  
5. **`__not_in_flash_func`** на всех горячих функциях (ISR, DSP-поллинг,    
   обработка отсчётов, `loop1`). При добавлении новой функции в горячий    
   путь — помечать обязательно.    
  
6. **SPSC-очереди без блокировок.** head пишет producer, tail — consumer,    
   `__dmb()` между записью данных и публикацией указателя. Не добавлять    
   мьютексы/критические секции в путь данных.    
  
7. **Порядок инициализации.** `af_dsp_init()` в `setup()` ДО    
   `af_capture_start()` — фильтры должны быть готовы к первому блоку.    
  
8. **Константы — только через `af_config.h`.** Не хардкодить частоты,    
   размеры буферов, пины в .cpp-файлах.    
  
9. **Core 1 никогда не блокируется.** Никаких Serial/delay/ожиданий    
   в `loop1()` и ISR — только `tight_loop_contents()` в `setup1()`    
   до старта захвата.    
  
10. **Не затенять имена SDK.** `clk_sys` — enum из hardware/clocks;    
    локальную переменную называть иначе (`f_sys`).    
  
11. **Захват: chain_to обязателен.** Два DMA-канала (A/B) перезапускают    
    друг друга аппаратно — программный рестарт в IRQ давал мёртвое время    
    и ~50% потерь блоков. Не возвращаться к одноканальной схеме.    
  
12. **PWM: DMA не стартует на пустых буферах.** `af_pwm_init` только    
    настраивает канал; `dma_channel_start` делает `af_pwm_poll` при    
    >=2 заполненных duty-буферах — иначе фазовая гонка и underruns    
    каждый блок. В IRQ перед рестартом обязателен `set_trans_count`.    
  
## Сборка и проверка    
  
pio run -e pico              # сборка    
pio run -e pico -t upload    # прошивка    
pio device monitor -b 115200 # терминал    
  
Проверка после изменений:    
- `stats` в Serial: `cap_dropped`, `out_dropped`, `clip` не должны расти    
- `core1: max_block_us` — пиковая стоимость блока, окно 2048 мкс    
  (512 отсчётов @ 250 ksps). Должно быть < 2048 с запасом    
- `pwm underruns` — 0 в установившемся режиме, `fill` = 1..3    
- boot-лог: `[UAC]`, `[GPIO]`, `[CAP]`, `# INIT_DONE`    
  
## Типичные задачи и куда смотреть    
  
- **Изменить полосу/частоты** — `af_config.h` (дефолты), CLI `band`,    
  CAT `SH`/`SL` или пин GP4 (пресеты `AF_BAND_WIDE_*`/`AF_BAND_NARROW_*`)    
- **Переназначить управляющие пины** — `AF_PIN_NT`, `AF_PIN_NR`,    
  `AF_PIN_BAND_WIDE` в `af_config.h`; логика — `af_gpio_ctl.cpp`    
- **Тюнинг NT/NR/AGC** — константы `NOTCH_*`, `NR_*`, `AGC_*`, `LIMIT_*`    
  в `af_config.h` выровнены 1:1 с приёмником; менять параметры,    
  а не структуру, если нет причины    
- **CW-режим** — `CW_*` в `af_config.h`, биквады `cw_push` и профиль    
  АРУ в `agc_limit` (`af_dsp.cpp`)    
- **Другой пин/частота АЦП** — `AF_ADC_PIN`, `AF_FS_ADC_HZ` в `af_config.h`;    
  при смене Fs пересчитать цепочку децимации (CIC/2 + 3×HB/2 = /16)    
- **Рост cap_dropped/scratch** — DSP не укладывается в окно 2048 мкс:    
  смотреть `max_block_us`, уменьшать `AF_FIR_N`/`NOTCH_N`, оптимизировать    
  `notch_lms_push` (скользящее окно для energy — известный резерв)    
- **PWM underruns** — смотреть `fill` в stats: 0 = очередь пуста    
  (продюсер не пишет), растёт = `af_pwm_poll` не вызывается    
- **CAT-команды** — парсер в `af_cli_poll` (`af_cli.cpp`), по образцу    
  `fldigi_cat.cpp` приёмника; новые команды добавлять туда же    
  
## Стиль    
  
- Комментарии на русском, как в исходных проектах    
- Имена: префикс `af_` для API, `snake_case`    
- Диагностика — через `Serial.printf` с префиксом `#` или `[TAG]`    
- Новые счётчики потерь — volatile uint32_t, выводить в `stats`
