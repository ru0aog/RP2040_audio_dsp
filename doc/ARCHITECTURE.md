# ARCHITECTURE.md — RP2040_audio_dsp  
  
Подробное описание архитектуры моноканального DSP-тракта НЧ на RP2040.  
Актуально для коммита 7bcc088.  
  
---  
  
## 1. Общая схема тракта
```
ADC GP26 (250 ksps, 12 бит, DMA)
└─> DC-EMA (убрание смещения, k=1/256)
└─> CIC-дециматор /2 (250k -> 125k)
└─> HB-фильтр /2 (125k -> 62.5k)
└─> HB-фильтр /2 (62.5k -> 31.25k)
└─> HB-фильтр /2 (31.25k -> 15.625k)
└─> Полосовой FIR 127 (симметричный, 300..2400/3000 Гц)
└─> CW-режим (опц.): шум -> 3×биквад Q19
└─> Автонотч NT (NLMS, опц.)
└─> Шумоподавление NR (LMS ALE, опц.)
└─> АРУ + лимитер
└─> fan-out: 2 SPSC-очереди
├─> PWM GP0 (~125 кГц, DMA)
└─> UAC-микрофон 44100/16
```
Частота дискретизации после децимации: **15.625 ksps** (OSR 16 относительно  
полосы). Выходная частота `AF_FS_OUT_HZ = 15625`.

## 2. Распределение по ядрам  
  
### Core 1 — real-time DSP  
  
| Задача | Файл | Описание |  
|---|---|---|  
| `loop1()` | `RP2040_audio_dsp.cpp` | Бесконечный вызов `af_dsp_poll()`; сторож `primask` |  
| `af_dsp_poll()` | `src/af_dsp.cpp` | Забирает ADC-блоки из SPSC-очереди, прогоняет весь тракт, публикует int16-блоки в обе выходные очереди |  
| Учёт загрузки | `src/af_dsp.cpp` | `core1_busy_us` — только время обработки блока (`t0` внутри `while(acquire)`); `core1_max_us` — пиковая стоимость блока |  
  
На Core 1 **нет** DMA-IRQ захвата — прерывания перенесены на Core 0,  
чтобы не конкурировать с DSP за время ядра.  
  
### Core 0 — обслуживание  
  
| Задача | Файл | Описание |  
|---|---|---|  
| `af_dma_irq()` | `src/af_capture.cpp` | DMA_IRQ_0: переключение каналов A/B, публикация блоков в очередь |  
| `af_pwm_poll()` | `src/af_pwm.cpp` | int16 -> duty-конвертация, заполнение кольца duty-буферов, отложенный старт DMA |  
| `af_usb_poll()` | `src/af_usb.cpp` | Ресемплинг 15.625k -> 44.1k, выдача в UAC-микрофон |  
| `af_cli_poll()` | `src/af_cli.cpp` | CLI по `\n` + Kenwood CAT по `;` |  
| `af_gpio_ctl_poll()` | `src/af_gpio_ctl.cpp` | Дебаунс GP2/GP3/GP4 -> nt/nr/band |  
| `loop()` | `RP2040_audio_dsp.cpp` | Вызывает все poll-функции + TinyUSB |

## 3. Захват: ADC + DMA (`src/af_capture.cpp`)  
  
### Двухканальный пинг-понг с `chain_to`  
  
- Два DMA-канала (A и B), каждый пишет в свою пару буферов + scratch.  
- `chain_to` настроен так, что по завершении блока канал **аппаратно**  
  запускает напарника — мёртвого времени на перезапуск нет.  
- `DMA_IRQ_0` живёт на **Core 0** (в отличие от первой версии, где IRQ  
  был на Core 1 и конкурировал с DSP).  
  
### Параметры  
  
| Параметр | Значение |  
|---|---|  
| `AF_ADC_PIN` | GP26 (ADC0) |  
| `AF_FS_ADC_HZ` | 250000 (clkdiv=191 от 48 МГц) |  
| `AF_BLOCK_SAMPLES` | 512 отсчётов = 2.048 мс |  
| `AF_NUM_BUFFERS` | 8 рабочих буферов в SPSC-очереди |  
| Темп блоков | ~488 блоков/с |  
  
### Диагностика захвата  
  
| Счётчик | Смысл |  
|---|---|  
| `isr` | Число DMA-прерываний (блоков) |  
| `q_full` | Очередь полна — блок потерян |  
| `scratch` | Оба буфера канала заняты — блок ушёл в scratch |  
| `busy` | Буфер не освобождён потребителем вовремя |  
| `fcs_over` | Переполнение FIFO АЦП |  
| `af_irq_both_pending` | Оба канала завершились до обработки IRQ — латентность IRQ > ~4 мс |

## 4. DSP-тракт (`src/af_dsp.cpp`)  
  
Весь горячий путь — целочисленный Q15/int64, без float, в RAM  
(`__not_in_flash_func`).  
  
### 4.1 DC-EMA  
  
`dc_est += ((meas << 8) - dc_est) >> 8` — скользящее среднее с k=1/256,  
вычитается из отсчёта. Порт `dc_i/dc_q` из приёмника.  
  
### 4.2 Децимация /16  
  
| Каскад | Тип | Частота |  
|---|---|---|  
| CIC /2 | гребёнчатый | 250k -> 125k |  
| HB1 /2 | полуполосный FIR | 125k -> 62.5k |  
| HB2 /2 | полуполосный FIR | 62.5k -> 31.25k |  
| HB3 /2 | полуполосный FIR | 31.25k -> 15.625k |  
  
Коэффициенты HB — 1:1 из `RP2040_receiver`. Третий каскад добавлен  
при переходе на 15.625 ksps (в приёмнике децимация /8 от 125 ksps —  
эквивалентный результат).  
  
### 4.3 Полосовой FIR  
  
- `AF_FIR_N = 127` отводов, Blackman-Harris, полоса 300..2400 Гц  
  (узкая) или 300..3000 Гц (широкая, по GP4).  
- **Симметричная реализация**: `y = Σ h[i]·(x[i] + x[N-1-i])` —  
  64 умножения вместо 127, экономия ~45% времени FIR.  
- Пересчёт коэффициентов при смене полосы — `af_dsp_set_band()`.  
  
### 4.4 CW-режим (`cw on`)  
  
- Аддитивный шум: LFSR -> `±512 × cw_noise/512`, подмешивается до фильтра.  
- 3 каскада биквадов Q19 (f0=700 Гц, bw=80/150 Гц) — `cw_push()`.  
- Медленный профиль АРУ (левелинг) вместо быстрого речевого.  
- Параметры: `AF_CW_F0_HZ`, `AF_CW_BW_HZ`, `cw noise <0..512>`.  
  
### 4.5 Автонотч NT (NLMS)  
  
| Параметр | Значение | Примечание |  
|---|---|---|  
| `NOTCH_N` | 24 | весов LMS |  
| `NOTCH_DELAY` | 96 | задержка декорреляции |  
| `NOTCH_MU_Q` | 2458 | шаг NLMS (Q15) — из приёмника |  
| `NOTCH_EPS` | 4096 | защита знаменателя — из приёмника |  
| `NOTCH_G_MAX` | 1<<20 | кламп шага — из приёмника |  
| `NOTCH_LEAK_SHIFT` | 10 | leaky-утечка весов |  
  
Деление `e·MU/den` заменено на сдвиг по старшему биту:  
`k = 63 - __builtin_clzll(den); g = (e·MU << 15) >> k` — шаг в пределах  
×2 от точного NLMS, кламп `G_MAX` ограничивает. Убрано ~0.5–0.7 мс/блок.  
  
### 4.6 Шумоподавление NR (LMS ALE)  
  
| Параметр | Значение |  
|---|---|  
| `NR_N` | 32 |  
| `NR_DELAY` | 5 |  
| `NR_MU_Q` | 1638 |  
| `NR_EPS` | 1<<21 |  
| `NR_G_MAX` | 1<<20 |  
| `NR_MAKEUP` | 65536 (1.0) |  
  
Та же `clzll`-замена деления. `taps[]` хранит индексы кольцевого буфера.  
  
### 4.7 АРУ + лимитер  
  
- Два профиля: речевой (быстрый) и CW (медленный левелинг).  
- `x·AGC_REF/avg` — int64-деление на отсчёт (кандидат на `clzll`-замену  
  при нехватке запаса).  
- Лимитер с счётчиком `clip`.  
  
### 4.8 Выходной fan-out  
  
`out_emit(s)` пишет отсчёт в **две независимые SPSC-очереди**:  
  
| Очередь | Потребитель | Блок |  
|---|---|---|  
| `out_pwm` | `af_pwm_poll()` (Core 0) | `AF_OUT_BLOCK_SAMPLES = 128` |  
| `out_usb` | `af_usb_poll()` (Core 0) | `AF_OUT_BLOCK_SAMPLES = 128` |  
  
У каждой очереди свой `fill_buf`/`head`/`tail`/`busy[]`/`dropped`.  
Общий `out_fill_pos` — позиция внутри заполняемого блока.

## 5. PWM-выход (`src/af_pwm.cpp`)  
  
### Схема  
  
- PWM-слайс на `AF_PWM_PIN` (GP0), `wrap = 999` (~10 бит duty).  
- `clkdiv` подобран под несущую **~125 кГц**:  
  `div = clk_sys / (1000 × 125000) = 1.76` при 220 МГц.  
- DMA-канал пишет duty в `pwm_hw->slice[n].cc`, темп — pacing-таймер  
  DMA на `AF_FS_OUT_HZ` (`den = 220000000/15625 = 14080`, точный).  
  
### Кольцо duty-буферов  
  
- **4 буфера** по 128 отсчётов (~64 мс slack при 15.625 ksps).  
- `DMA_IRQ_1` по завершении блока ищет **любой готовый** буфер по кольцу  
  (не жёсткий пинг-понг), перезапускает канал с `set_trans_count` +  
  `set_read_addr`.  
- `underrun` — только если все 4 буфера пусты.  
  
### Отложенный старт  
  
`af_pwm_init()` **не** запускает DMA — только настройку. `af_pwm_poll()`  
стартует канал, когда заполнены ≥2 duty-буфера. Убирает фазовую гонку  
«IRQ раньше заполнения», которая давала underrun на каждый блок.  
  
### Внешняя схема  
  
RC-фильтр на GP0: 2 каскада 1к/22нФ (срез ~7 кГц) + разделительный  
конденсатор 0.47–1 мкФ на линейный вход. Несущая 125 кГц давится  
~50 дБ двухкаскадным фильтром.

## 6. USB-выход (`src/af_usb.cpp`)  
  
- UAC-микрофон 44100/16/stereo (TinyUSB).  
- Ресемплинг 15.625k -> 44.1k в `af_usb_poll()`.  
- Очередь `out_usb` — та же структура, что `out_pwm`.  
- `usb: dropped` — счётчик потерянных блоков.

## 7. Управление  
  
### CLI (`src/af_cli.cpp`)  
  
Два синтаксиса в одном парсере:  
  
**Обычные команды** (по `\n`): `help`, `stats`, `nt on|off`, `nr on|off`,  
`cw on|off`, `cw freq <Hz>`, `cw bw <Hz>`, `cw noise <0..512>`,  
`band wide|narrow`, `agc on|off`.  
  
**Kenwood CAT** (по `;`, порт из `fldigi_cat.cpp` приёмника):  
  
| Команда | Действие |  
|---|---|  
| `ID;` | Ответ `ID019;` |  
| `NT;` / `NT0;`/`NT1;`/`NT2;` | Чтение/установка нотча |  
| `NR;` / `NR0;`/`NR1;`/`NR2;` | Чтение/установка NR |  
| `SH;` / `SHxx;` | Верхняя граница полосы (xx×100 Гц) |  
| `SL;` / `SLxx;` | Нижняя граница полосы |  
| `MD;` / `MDx;` | Режим (MD3 -> CW on) |  
| `FA;`, `IF;`, `TX;`, `RX;` | Заглушки совместимости |  
  
### GPIO (`src/af_gpio_ctl.cpp`)  
  
| Пин | Функция | Активный уровень |  
|---|---|---|  
| GP2 | NT on/off | LOW = вкл |  
| GP3 | NR on/off | LOW = вкл |  
| GP4 | Полоса wide/narrow | LOW = широкая |  
  
Дебаунс: опрос 10 мс, 4 стабильных чтения (~40 мс).

## 8. Бюджет времени Core 1  
  
Окно обработки блока: **2048 мкс** (512 отсчётов @ 250 ksps).  
  
| Конфигурация | `max_block_us` | Запас |  
|---|---|---|  
| Все фильтры выкл | ~1180–1280 | ~800 мкс |  
| `nt on` | ~2038–2063 | ~10 мкс (на грани) |  
  
`core1_load` — честная загрузка (busy только внутри обработки блока):  
~56% без фильтров, ~98% с `nt on`.  
  
### Резервы разгрузки (если понадобятся)  
  
1. Скользящее окно для `energy` в `notch_lms_push` — убрать O(N)  
   пересчёт, ~300 мкс.  
2. `clzll`-замена деления в `agc_limit` — ~100 мкс.  
3. `NOTCH_N` 24->16 — нотч шире, ~200 мкс.  
4. `AF_FIR_N` 127->95 — ~300 мкс, переходная полоса шире.


## 10. Отличия от RP2040_receiver (откуда портировано)  
  
| Аспект | Приёмник | audio_dsp |  
|---|---|---|  
| Вход | I/Q, 125 ksps | Моно, 250 ksps |  
| Децимация | /8 -> 15.625k | /16 -> 15.625k |  
| FIR | 63, Blackman | 127, Blackman-Harris, симметричный |  
| NT/NR | Только в SSB | Всегда (по флагам) |  
| FFT (RSID) | На Core 1, нарезан квантами | Нет |  
| IRQ захвата | Core 1 | Core 0 |  
| Выход | PWM | PWM + UAC-микрофон |  
| Команды | Kenwood CAT | CLI + Kenwood CAT |
