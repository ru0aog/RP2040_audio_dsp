## CHANGE-001: Реорганизация консольных команд и полный снимок в банках  
  
**Статус:** внедрено (коммиты `620e6ff`, `bfa5e1d`, `49c1c31`,  
`e65d943`, `8be2807`).  
  
### Что изменено  
  
**1. Все настраиваемые параметры выведены в команды.**  
Дефайны `af_config.h` остались значениями по умолчанию — теперь они  
инициализируют `static volatile`-переменные, которые меняются  
командами с Core 0. Сеттеры с клампами, вне горячего пути.  
  
- RX (`af_dsp.cpp`): `agcref`, `agcmax`, `agcmin`, `limceil`,  
  `nrdepth`, `nrmakeup`, `ntmu`, `nrmu`. CW-ветка АРУ  
  (`CW_AGC_*`) осталась на дефайнах — команды меняют только  
  SSB-варианты.  
- TX (`af_tx.cpp`): `txcompthr`, `txcompthrlo`, `txcompthrhi`,  
  `txsplit`, `txgatehold`, `txgatehyst`, `txagcmax`, `txinteltgt`,  
  `txintelcut`, `txintelboost`, `txpresfreq`, `txpresq`,  
  `txshelffreq`, `txshelfq`, `txnotchf`.  
- Расчёты биквадов вынесены из `af_tx_init` в `tx_xo_design()`,  
  `tx_pres_design()`, `tx_notch_design()` — сеттеры частот  
  пересчитывают коэффициенты на лету. `txsplit` пересчитывает и  
  LR2-кроссовер, и `AF_TX_SPLIT_K_Q15` (старый комплементарный  
  split для `txlr2 off`).  
  
**2. `help` структурирован по секциям:**  
`# === ПРИЁМ (RX) ===`, `# === ПЕРЕДАЧА (TX) ===` (порядок — по  
цепочке тракта), `# === СИСТЕМА ===`, `# === GPIO ===`.  
`stats` дополнен всеми новыми полями.  
  
**3. Банк = полный снимок RX+TX (`AF_STORE_VER` 3→4).**  
`af_bank_t` расширен с 9 до ~50 полей (~90 байт/запись):  
все RX-параметры АРУ/лимитера/NR/NT + весь TX-тракт.  
`AF_EEPROM_SIZE` 256→1024. `banks clr` заполняет банки через  
`bank_fill_defaults()` (дефолты из `af_config.h` + рабочая точка  
`tx_apply_profile`), per-банк переопределяются только RX-поля.  
Вывод `banks` — 5 строк на банк.  
  
**Не хранятся в банке (осознанно):** `nt_on`, `nr_on`,  
`rxnotch_on` — фильтры включаются по шумовой обстановке через  
GP5/GP6/консоль, а не пресетом.  
  
### Подводные камни (для будущих правок)  
  
1. **Порядок в else-if цепочке `cli_exec`.** Команды с общими  
   префиксами через `strncmp` (`txpres`, `txnotch`, `txshelf`,  
   `txintel`, `txduck`, `txexc`) перехватывают более длинные  
   имена — `txpresfreq`, `txnotchf`, `txshelffreq`, `txinteltgt`  
   и т.п. обязаны стоять **раньше** коротких. Новые команды  
   добавлять через `strcmp` (точное совпадение) — тогда порядок  
   не важен.  
2. **Порядок сеттеров в `af_store_load`.** `af_tx_set_shelf`  
   вызывается после `shelffreq`/`shelfq` — иначе пересчёт  
   биквада пойдёт со старым усилением. Аналогично `presmax`  
   после `presfreq`/`presq`.  
3. **Правило версионирования:** новые поля в `af_bank_t` →  
   `AF_STORE_VER` +1 → обновить `bank_fill_defaults` и вывод  
   `banks`. Старый формат форматируется автоматически при старте.  
4. **`save N` ребутит без echo** — данные уже во flash, это  
   штатно, не зависание.  
5. **Перепрошивка стирает банки** — сектор хранилища в конце  
   flash затирается mass-erase. После прошивки `banks` покажет  
   `empty` — это норма, восстановить через `banks clr`.

## CHANGE-002: Табличный stats, команда dump, профили TX по таблице  
  
**Статус:** внедрено (коммиты `1972cd4`, `4c00dfa`, `e89c90d`,  
`cb5f436`, `4a744b7`, `b933295` + правки txprof/txsetdef).  
  
### Что изменено  
  
**1. `stats` — таблица параметров по секциям.**  
  
Вывод перегруппирован в три секции:  
  
- `# === RX (active|inactive) ===` — параметры приёмного тракта:  
  band, nt, nr, bypass, ramp, cw (f0/bw/noise), agc, gain,  
  agcref/agcmax/agcmin, limceil, nrdepth/nrmakeup, ntmu/nrmu.  
- `# === TX (active|inactive) ===` — параметры передающего тракта  
  по цепочке: band, mode, comp/clip, agc/agcmax, gate/hold/hyst,  
  gfloor, ap/2band/split/lr2, compthr lo/hi, pres, shelf, duck,  
  exc, intel, notch + диагностические огибающие `txenv`.  
- `# === SYS ===` — системные параметры (действуют в обоих  
  режимах): mode, bank (код GP2–GP4), voice, pwm, usb mounted,  
  core0/core1 load, max_block_us, счётчики cap/out, fs.  
  
Обе секции RX и TX печатаются всегда — параметры неактивного  
тракта настраиваются командами и должны быть видимы.  
  
**2. Периодический вывод из `loop()` удалён, введена команда `dump`.**  
  
- `dump` — однократный инженерный дамп: дельты счётчиков  
  (cap/out/usb/pwm), `usb_ur_t`/`pwm_ur_t`, поля ресемплера  
  (short/rs/rpr/gap/ff/ws/av).  
- `dump N` — вывод каждые N секунд (тик в `af_cli_poll`,  
  неблокирующий); `dump 0`/`dump off` — остановка.  
- Дельты считаются с прошлого вызова `dump`, а не за фиксированные  
  10 с — при `dump 5` каждая строка = приращение за 5 с.  
  
**3. Вердикт самодиагностики в конце `dump`.**  
  
Проверки по цепочке «источник → потребитель»:  
  
- `cap`: dropped/scratch/q_full/fcs_over — потери захвата;  
- `core1`: load > 95%, max_block_us > 4096 мкс (окно блока);  
- `out`: dropped USB/PWM;  
- `usb`: reprimes (очередь до дна) — только при читающем хосте;  
- `pwm`: реальные underruns (`af_pwm_underruns`), не счётчик  
  опросов пустой очереди;  
- `clip`: клиппинг выхода.  
  
Итог: `# OK: потерь нет, тракт здоров` или список `# WARN ...`.  
При нечитающем USB-хосте — `# INFO usb: хост не читает поток`  
(гейт по `af_usb_rs_adj_mhz() > -40000`: rs=-48000mHz = буфер  
полон, поток не потребляется).  
  
**4. Профили TX перенумерованы по таблице FLAT=1 … MAX=7.**  
  
`tx_apply_profile` переписана: каждый case — полный  
самодостаточный снимок всех сеттеров `af_tx_*` (без базиса),  
порядок «от прозрачного к плотному»: 1=flat, 2=natural, 3=dx,  
4=bass, 5=whisper, 6=loud, 7=max. Имена в `txprof` обновлены,  
`work` → подсказка `txsetdef`.  
  
**5. `txpreset` удалён, введён `txsetdef`.**  
  
`txsetdef` — сброс TX к дефолтам `af_config.h` (бывший  
`txpreset def`). Частичные пресеты `aggro`/`max`/`flat` убраны —  
их роль выполняют `txprof 1..7`.  
  
### Подводные камни  
  
1. **`urU`/`urP` в дампе — НЕ underruns.** Это счётчики «запрос  
   при пустой очереди» (`af_dsp_out_underruns_*`): растут всегда,  
   когда потребитель опрашивает чаще, чем Core 1 публикует.  
   Реальные пропуски — `af_pwm_underruns` (`pwm: ur`) и  
   `af_usb_reprimes` (`rpr`). Не использовать `urU/urP` в  
   диагностике — ложные WARN (см. BUG-009).  
2. **`af_usb_blocks_rx` растёт и без читающего хоста** — буфер  
   AudioTools заполняется независимо от потребления. Признак  
   «хост читает» — `rs_adj_mhz > -40000`, не `blocks_rx`.  
3. **`af_q_fill_max` — кумулятивный максимум с boot.** WARN по  
   нему означает «бывало переполнение», а не «переполнено  
   сейчас».  
4. **Порядок сеттеров в `tx_apply_profile`:** частоты/Q до  
   `presmax`/`shelf` (пересчёт биквадов), `txsplit` при  
   включённом `tx2band`.  
5. **`txsetdef` не трогает `af_tx_set_notch`** — on/off нотча при  
   сбросе сохраняется (частоты сбрасываются). Осознанно.

## CHANGE-003: Озвучка профилей банков  
  
**Статус:** внедрено (коммиты `0943d38`, `33da2b1`).  
  
### Что добавлено  
  
**1. Голосовые клипы «профиль один…семь»** — `af_voice.h`:  
enum расширен `VOICE_PROF_1..VOICE_PROF_7` (id 07–13), в  
`af_voice.cpp` добавлены `clip_voice_07..13` и include'ы  
`voice_07.inc..voice_13.inc`. Клипы записаны тем же конвейером  
`WAV_convertor.py` (8 кГц mono → int16-массив).  
  
**2. Озвучка при загрузке банка** — `af_gpio_ctl.cpp`,  
`apply_bank`: после успешного `af_store_load(code)` играет  
`af_voice_play(VOICE_PROF_1 + code - 1)`. Порядок в очереди:  
«профиль N» → «АРУ выключена» (если в банке agc=off) →  
«телеграфный фильтр включен» (если cw=on). Очередь 4 элемента —  
влезает.  
  
**3. Озвучка при `load N` из консоли** — `af_cli.cpp`: та же  
строка `af_voice_play(VOICE_PROF_1 + idx - 1)` в ветке успешной  
загрузки. Пустой банк и `load 0` молчат.  
  
### Подводные камни  
  
1. **Имя «профиль» ≠ `txprof`.** Голос «профиль N» озвучивает  
   *банк* N (снимок RX+TX из flash), а не таблицу `txprof`  
   (FLAT…MAX в коде). Совпадение содержимого — только если банк  
   был сохранён после `txprof N` → `save N`.  
2. **`WAV_convertor.py` пишет `voice_.inc`/`clip_voice`** —  
   после конвертации файл и символ переименовываются вручную в  
   `voice_XX.inc`/`clip_voice_XX`. При добавлении клипов не  
   забыть.  
3. **Ручной режим молчит** — отпускание пинов (`code == 0`) и  
   `load 0` голос не играют: отпускание — не событие.  
4. **Нет клипа «режим обхода выключен»** — `VOICE_BYPASS_OFF`  
   в enum отсутствует осознанно; bypass озвучивается только  
   при включении.

## CHANGE-004: Перезапись хранилища банков — без EEPROM, без ребута  
  
**Статус:** внедрено (коммиты `fbcd8b5` … `1b7906d`, см. BUG-010).  
  
### Что изменено  
  
**1. Чтение — напрямую из XIP, EEPROM исключён.**  
`af_store_init` читает сектор `AF_FLASH_OFF` в `s_sector_img`  
через `memcpy` из `XIP_BASE`; `af_store_read`/`banks`/`load`  
читают из `s_sector_img`. EEPROM-эмуляция больше не  
используется — устранено расхождение секторов при сборке под  
другой размер flash.  
  
**2. Запись — SDK-обёртки + жёсткий сброс Core 1.**  
`do_flash_write` (`__not_in_flash_func`): `flash_range_erase` +  
`flash_range_program`. Перед записью `multicore_reset_core1()`  
+ `set_sys_clock_khz(125000)` (как `vfo_clk_boost_exit` в  
маяке), после — `af_set_clk()` (PLL + vreg + верификация) и  
`rp2040.restartCore1()`. Ребут убран — `save N`/`banks clr`  
возвращаются в CLI.  
  
**3. `af_store_init` — read-only.** Пустой/чужой сектор →  
`[STORE] sector blank/foreign`, банки `empty`. Форматирование  
только через `banks clr`. Boot-путь не пишет flash — нет  
зависаний на старте.  
  
**4. `af_store_save` гарантирует magic.** Перед записью записи  
проверяется заголовок сектора; при отсутствии magic сектор  
инициализируется — `save` на пустом секторе больше не теряет  
банк.  
  
### Подводные камни  
  
1. **`af_set_clk()` может откатить на 133 МГц** — при ошибке  
   верификации >1%. После `save` проверять `stats`: `clk_sys`  
   должен быть 250 MHz.  
2. **`rp2040.restartCore1()`** — метод класса `RP2040` ядра  
   Philhower; перезапускает `setup1`/`loop1` штатно. DSP на  
   Core 1 встаёт на ~мс — короткий провал в аудио при `save`.  
3. **`AF_FLASH_OFF = 0x1FF000`** — последний сектор 2 МБ,  
   фиксированный (не от `PICO_FLASH_SIZE_BYTES`). На 4-МБ платах  
   работает как обычный сектор внутри чипа.  
4. **Мёртвый код парковки** (`park_core1`, `g_park_req`,  
   `g_parked`, `af_store_core1_park_poll`) оставлен в файле —  
   не используется, удалять аккуратно вместе с вызовом в  
   `setup1`.  
5. **`src/af_rec.cpp`** — `slot_erase_sector`/`slot_program`  
   должны быть на тех же SDK-обёртках; прямые ROM-вызовы без  
   `enter_cmd_xip` висят тем же образом (см. BUG-011).  

6. **`clock_configure(clk_sys)` затирает `ssi_hw->baudr`** —  
   в `reprogram_pll` делитель флеша писать строго ПОСЛЕ  
   `clock_configure` (коммит `d08ebcd`, см. BUG-012). Симптом  
   регрессии: `stats` → `flash_sck=1.5 MHz (BAUDR=162)`,  
   `core1 load` ~100%, `cap dropped` растёт.  

## af_rec: RAM-магнитофон с децимацией ×2 (2026-11)  
  
### Архитектура  
- Запись только в RAM: ram_buf[AF_REC_RAM_SAMP=60000], ~117 КБ.  
- Децимация ×2 при записи (AF_REC_DECIM=2): каждый 2-й отсчёт,  
  15464 -> 7732 Гц, ~7.8 с в буфере.  
- Воспроизведение: линейная интерполяция ×2 (midpoint между  
  соседними отсчётами) обратно в 15464 Гц.  
- Flash не используется — запись не персистентна.  
- Источник записи — активный тракт после всех обработок.  
  
### Пины (af_gpio_ctl.cpp)  
- GP9 (LOW) -> запись: тракт в TX (микрофон), БЕЗ PTT; open -> стоп+RX.  
- GP10 (LOW) -> воспроизведение: тракт в TX + PTT на GP8 (как выход,  
  LOW) + звук в TX-тракт; open/конец буфера -> стоп+RX.  
- GP8 — двойная роль: вход PTT / выход PTT при playback.  
  Флаг sw_ptt_active отсекает входную ветку GP8 на время play.  
- Добиватели в af_gpio_ctl_poll: авто-стоп по буферу при нажатом  
  GP9/GP10 возвращает тракт в RX и отпускает PTT.  
- Приоритет: play > rec; ручной PTT во время play игнорируется.  
  
### CLI (af_cli.cpp)  
- rec: включает TX-тракт (микрофон) сам — флаг cli_rec_tx,  
  возврат в RX по stop/авто-стопу (добиватель в af_cli_poll).  
- play: OK печатается ПОСЛЕ окончания — флаг cli_play_pending.  
- tx off: заблокирован во время rec/play (ERR ... active).  
- Секунды везде: len * AF_REC_DECIM / AF_FS_OUT_HZ.  
  
### Файлы  
- src/af_rec.h — AF_REC_RAM_SAMP, AF_REC_DECIM, AF_REC_MAX_SAMP  
  (теперь = AF_REC_RAM_SAMP, не от flash-слота).  
- src/af_rec.cpp — RAM-only, без flash/af_store/park-кода.  
- src/af_gpio_ctl.cpp — apply_rec/apply_play, sw_ptt_active.  
- src/af_cli.cpp — cli_rec_tx, cli_play_pending, tx off guard.  
  
### Проверено на железе  
GP9: запись 7.7 с, авто-стоп -> RX. GP10: TX+PTT+звук -> RX.  
CLI rec/play/stop/recs/tx off — все сценарии, перезапись буфера.  

## af_rec: voice_14-заглушка при пустом буфере (2026-11)  
  
### Поведение  
Если с момента старта платы записи в RAM-магнитофон не было  
(rec_len == 0), воспроизведение (GP10 или CLI `play`) играет  
клип-заглушку `clip_voice_14` из `src/voice/voice_14.inc`  
(84447 отсчётов @ 15464 Гц ≈ 10.9 с, полная частота, без  
интерполяции). После первой записи — переключается на RAM-буфер  
навсегда (до ребута; RAM не персистентна).  
  
### Реализация (src/af_rec.cpp)  
- `play_src` (0=ram, 1=voice14) и `play_len` — выбираются в  
  `af_rec_play()`: `rec_len > 0` → ram_buf с интерполяцией ×2,  
  иначе → clip_voice_14 1:1.  
- `af_rec_mix`/`af_rec_src` — ветка voice14 читает `clip_voice_14[pos++]`  
  напрямую (клип уже на выходной частоте, децимация не нужна).  
- `af_rec_play_len()` — длина текущего воспроизведения  
  (clip_voice_14_len или rec_len); используется в CLI для  
  корректных секунд в `OK play`.  
- `clip_voice_14` — const во flash, читается с Core 1 через XIP.  
  Безопасно: flash-записи во время play не бывает (дамп удалён;  
  af_store пишет только при остановленной Core 1).  
  
### CLI play voice_14 — через TX+PTT (src/af_cli.cpp, af_gpio_ctl.cpp)  
- `play` при пустом буфере: `af_gpio_ptt_tx_on()` (GP8 -> OUTPUT LOW,  
  af_dsp_set_tx(1)) + `af_rec_play()` — клип идёт через весь TX-тракт  
  (компрессор/клиппер/АРУ) на GP1, как при GP10.  
- Флаг `cli_play_ptt` — добиватель в `af_cli_poll`: `OK play` печатается  
  ДО `af_gpio_ptt_tx_off()` (иначе тракт показывался бы rx).  
- `stop` во время voice_14-play: `af_rec_stop()` + `af_gpio_ptt_tx_off()`.  
- `af_gpio_ptt_tx_on/off` — экспортированы из af_gpio_ctl; общий  
  `sw_ptt_active` отсекает входную ветку GP8 и GP10-ветку на время  
  CLI play. Добиватель в `af_gpio_ctl_poll` (`sw_ptt_active &&  
  !af_rec_is_playing()`) покрывает и CLI-случай.  
  
### Проверено на железе  
Ребут -> `play`: `play 84447 samp (voice14)` -> `OK play: tx тракт, 10 с`.  
GP10: `play on (tx+ptt)` -> `play end -> ptt/tx released`.  
После `rec`: `play NNNNN samp (ram)` — и пин, и CLI играют запись.  

## af_cli: единая таблица параметров AF_PARAMS (2026-11)  
  
### Идея  
Одна таблица `AF_PARAMS[]` описывает все параметры банка:  
{ метка, тип, offsetof(af_bank_t, поле), сеттер }.  
Используется дважды:  
- печать `banks` — строки = параметры, столбцы = банки;  
- диспетчер команд — метка из таблицы = CLI-команда.  
Новая строка в таблице = новая команда + новая строка вывода.  
Рассинхронизации «команда есть, в таблице нет» не бывает.  
  
### Формат `banks`  
Транспонированная таблица: столбцы = `cur` + ячейки 1..7.  
- `cur` — снимок текущего состояния DSP через  
  `af_store_snapshot()` (сбор полей вынесен из `af_store_save`).  
- Пустая ячейка — `-----` во всех строках её столбца.  
- Ширина ~75 символов (param 14 + 8 столбцов по 7).  
- `banks clr` после записи падает в таблицу — сразу видно дефолты.  
  
### Табличные команды  
`cli_param_try()` вызывается в `cli_exec` ДО strtok (строка целая).  
Метка с пробелами + значение: `tx pres f 2500`, `band lo 500`,  
`tx duck off`. Без значения — чтение: `tx gate hys` -> `= 7`.  
- Longest-match: `tx gate hys` не перехватывается меткой `tx gate`.  
- Типы: PT_U8/U16/I16 (по размеру поля!), PT_ONOFF (on/off/1/0),

- Парсинг дробных: `p_parse_val` — `1.5` -> 150 для X100/GAIN.  
- Старые однословные команды (`band 300 2200`, `txpresmax 30`)

  промахе управление падает в старый else-if.

  # DEV.md — план потоковой записи звука во flash  
  
## Цель  
  
Непрерывная запись НЧ-потока во flash ~40-50 с (вместо текущих ~6.5 с в RAM),  
без большого RAM-буфера. Запись идёт параллельно с работой приёмника.  
  
## Ключевая идея  
  
Пока Core 0 пишет во flash (окно с IRQ-off), Core 1 продолжает сбор и  
децимацию потока ADC в маленький RAM-ринг. Core 0 между окнами забирает  
готовые int16-блоки и пишет их чанками в rec-slot.  
  
## Ограничения (из пройденного опыта, баг 4)  
  
- Во время flash-операции XIP выключен: весь код, работающий в окне,  
  обязан быть RAM-резидентным (`__not_in_flash_func`), включая всё,  
  что он вызывает.  
- Несколько `flash_range_program` в одном окне висят — одна операция  
  на окно (erase ИЛИ program).  
- Окно ~45 мс: park core1 → nominal 125 МГц → capture_pause → pwm off →  
  usb_muted → IRQ-off → flash op → flush_cache → IRQ-on → resume →  
  unmute → 250 МГц → pwm restore → unpark.  
- Схема окна уже отработана в `af_store.cpp` (`af_store_save`,  
  `af_store_test_iter`) — переиспользовать.  
  
## Архитектура  
  
Core 1 (RAM-резидентный дециматор):
ADC FIFO -> CIC /4 -> HB /2 -> HB /2 -> HB /2 (15.464 ksps)
-> int16-блоки -> rec-ring (SPSC, ~2-4 КБ, хватает на erase-окно)

Core 0 (писатель):
rec-ring -> сборка чанка 256 Б -> flash_range_program (1 на окно)
erase следующего сектора — отдельным окном, чередуя с program
заголовок записи — последним, по окончании

  
## Размеры  
  
- Поток: 15.464 ksps × 2 Б = ~31 КБ/с.  
- 50 с ≈ 1.5 МБ — НЕ влезает в rec-slot 764 КБ (0x140000..0x1FEFFF).  
  Варианты: ~24 с в 764 КБ; 8-битные отсчёты (~50 с); расширить слот  
  за счёт свободной зоны 0x101000..0x13FFFF (252 КБ) — итого ~1 МБ.  
- Ринг на erase-окно: 45 мс × 31 КБ/с ≈ 1.4 КБ — берём 4 КБ с запасом.  
  
## Что нужно сделать  
  
1. RAM-резидентный дециматор на Core 1: продублировать/перенести  
   CIC+HB-цепочку в `__not_in_flash_func`, проверить отсутствие  
   вызовов во flash (float-библиотеки, memcpy — только ROM-safe).  
2. Rec-ring SPSC int16-блоков (~4 КБ) между Core 1 и Core 0.  
3. Писатель на Core 0: чередование окон program(256 Б)/erase(4 КБ),  
   темп ~1 окно на 8-16 чанков, чтобы erase-окна не дробили запись.  
4. Заголовок записи (magic, длина, fs, дата) — пишется последним.  
5. Команды: `rec start/stop`, статус в `fmap`/`stats`.  
6. Стражи: не пересекаться с банками (0x1FF000) и прошивкой  
   (конец ~0x112000); отказ при нехватке слота.  
  
## Риски  
  
- Дрейф частоты: RAM-дециматор и DMA-цепочка должны давать  
  идентичный поток — иначе на стыке окна будет фазовый разрыв.  
- Erase-окно (4 КБ, ~45 мс) — самое длинное; ринг должен его  
  переживать без overrun.  
- Износ flash: ~25 секторов на запись, ~100k циклов — не проблема.  
- Тестовая матрица: `ftest`-подобный прогон записи 50 с + verify  
  чтением, контроль `out: dropped`, `usb: ur`, щелчков на стыках.  
  
## Отложенные/отклонённые варианты  
  
- Дамп RAM-буфера по stop — проще, но ограничен ~6.5 с (100 КБ RAM).  
- Потоковая запись без RAM-дециматора (пауза capture на каждое окно)  
  — дырка ~45 мс каждые 0.26 с, отклонено.  

## af_fm: найденные баги и их причины (2026-11)  
  
### FAT: короткие цепочки -> запись в чужой слот  
Цепочки FAT размечались по фактическому размеру файла  
(`fat_chain(f, first, wav_clusters[i])`). Между концом короткой  
цепочки и началом следующего файла оставались «дыры» — кластеры,  
свободные по FAT, но принадлежащие чужой LBA-территории.  
Windows при замене файла (delete+create) выделяет первые свободные  
кластеры -> данные REC7.WAV попадали в область REC3.  
Симптом: «заменял 7, записался 3».  
Фикс: полные цепочки `AF_FM_WAV_CLUSTERS` для всех RECn и  
`AF_FM_SET_CLUSTERS` для SET.TXT. Свободен только пул в конце  
диска (AF_FM_FREE_SECTORS) — туда пишутся новые данные, а  
`dir_track` мапит их в слот по имени файла из dir-записи.  
  
### Инцидент REC1: кластер 13 внутри SET.TXT  
SET.TXT имел цепочку по факту (~2 кластера из 16). Windows  
выделила новому REC1.WAV кластер 13 — территория SET.TXT.  
RIFF-заголовок ушёл в LBA 23 (data-область SET.TXT), парсер  
банков съел WAV-данные («SET.TXT parsed, 424 fields»).  
Фикс: `fat_chain(f, 2, AF_FM_SET_CLUSTERS)` — вся территория  
занята (ee5bb9c).  
  
### Слот 7 за границей flash -> зависание  
AF_REC_FLASH_OFF=0x140000, 7 слотов x 128 КБ -> слот 7 на  
0x200000, за пределами 2 МБ flash. Запись в банк 7 вешала плату  
(erase/program по несуществующему адресу).  
Фикс: слоты сдвинуты на 0x11E000 (конец 0x1FDFFF, зазор 4 КБ  
до banks @0x1FF000). Правило: проверять `fmap` — rec_slot не  
должен выходить за flash=2048 KB.  
  
### ul_push: сдвиг окна интерполяции  
`cur_in = ul_in_pos * AF_FM_REC_RATE` — окно считалось от  
текущего входного отсчёта вместо предыдущего: ломался  
апсемплинг (вход < 7732 Гц).  
Фикс: `cur_in = (ul_in_pos - 1) * AF_FM_REC_RATE`.  
  
### Парсер SET.TXT (af_cli_apply_set_txt)  
- `PT_FLOAT` не существует в ptype_t — float-форматы это  
  PT_GAIN (x256) и PT_X100 (x100), разбор через strtof.  
- `bank_field_set(&bk[col], best->off, val)` — двойной баг:  
  неверная сигнатура (нужен af_param_t*, не off) и bk[7] —  
  выход за границу (bk индексируется 0..6, col идёт 1..7 ->  
  `bk[col-1]`).  
- `strtol("on")` = 0 — токены on/off для PT_ONOFF надо  
  разбирать строкой, иначе `on` записывался как off.  
- Запись в пустой банк: проверка `bv[col-1]` (af_store_read)  
  до bank_field_set.  
  
### Пере-энумерация: когда нужна и когда вредна  
- Без re-enumerate после аплоада Windows показывает старый  
  файл (кеш FAT/dir) — слот записан, play играет новое, а  
  проводник — старое.  
- Безусловный вызов в setup() -> диск мигает через ~5 с после  
  каждого старта. Фикс: флаг fm_sizes_changed, выставляется  
  только при «пусто -> непусто» (wav_sizes 44 -> >44) и  
  принудительно в ul_commit. Первый sync — базовая линия  
  (first_sync), без флага.  
- Прямой вызов af_usb_reenumerate() в rec_fill_empty_slots  
  обходил флаг -> мигание при каждом старте. Фикс: вызывать  
  только если fill реально что-то записал.  
- Детект «пусто»: wav_sizes пустого слота = 44 (только  
  заголовок), не 0 — сравнение с 0 не срабатывало никогда.  
  
### Flash-окно в af_rec_init -> deadlock  
rec_slot_write (park core1 + даунклок + IRQ-off) в af_rec_init  
до запуска Core 1 -> park ждёт ядро, которое не работает.  
Фикс: ленивая заливка пустых слотов в af_rec_poll (Core 1 уже  
запущен, watchdog обслуживается).  
  
### Диагностика, которая помогла  
- `write hit RECn area, lba=N` в msc_write — видно, в чью  
  территорию реально пишет хост.  
- `dir RECn.WAV -> cluster N` в dir_track — видно, какой  
  кластер Windows выделила файлу (0 = delete).  
- hex-дамп первых 32 байт при bad WAV header — показал  
  A-law (tag 6, fmt size 18) вместо PCM.  
- Возврат OK вместо -1 при bad header — иначе Windows ретраит  
  сектор бесконечно (сотни строк в логе).

## CHANGE-005: RTTY-передатчик 45.45/170 (коммиты `b53b9a6`…`27398a5`)  
  
**Статус:** внедрено, валидировано fldigi + спектроанализатором.  
  
### Архитектура (`src/modes/rtty_tx.cpp`)  
  
- **CPFSK**: один NCO (LUT-синус 256), на границе бита переключается  
  только шаг фазы mark↔space — непрерывная фаза, без щелчков.  
  mark=1085 Гц, space=915 Гц (центр 1000, shift 170).  
- **Посылка**: start(space,1бит) + 5 бит LSB-first + stop(mark,1.5бита).  
  Между символами — mark (idle), в конце — хвост mark ~100 мс и тишина.  
- **Кодировка**: ASCII→ITA-2 (LTRS/FIGS), кириллица UTF-8→МТК-2 (RUS).  
  Сдвиги регистров вставляются автоматически при смене алфавита  
  (LTRS=0x1F, FIGS=0x1B, RUS=0x00). Строчные→заглавные, Ё→Е.  
- **Разделение по ядрам** (как cwtx): Core 0 — `rttytx_send/poll`  
  (кодирование, бит-автомат, эхо OLED), Core 1 — `rttytx_sample()`  
  (NCO + выбор шага). Между ними pending-слот `tx_pend_*` — Core 0  
  кладёт бит вперёд, Core 1 подхватывает на границе (см. BUG-013.1).  
  
### Выходной фильтр (`src/af_tx.cpp`)  
  
- Отдельный экземпляр `tx_fir_t` — каскад 2×127 тапов, полоса  
  `TX_RTTY_LO/HI_HZ` = 700/1400. Дизайн через `tx_rtty_fir_design()`:  
  подмена `tx_lo/hi_hz` на время `tx_fir_design_n` (save/restore).  
- `af_tx_rtty_fir_push(rttytx_sample())` в TX-ветке `af_dsp_poll`.  
- Амплитуда `RTTYTX_AMP 14000` — запас под `norm=2/sum` фильтра  
  (пиковый gain до +6 дБ на проход, +12 дБ каскадом) — см. BUG-013.4.  
  
### Интеграция  
  
- `af_dsp.cpp`: `af_dsp_rttytx_start/busy/started/clear_started` —  
  обёртки по образцу `af_dsp_cwtx_*`; взаимоисключение с cwtx.  
- `RP2040_audio_dsp.cpp`: `rttytx_poll()` в `loop()` + авто-возврат  
  в RX по `started && !busy` (рядом с блоком cwtx).  
- `af_cli.cpp`: `rtty tx <текст>` (strtok(NULL,"") — весь остаток),  
  `rtty abort`. Буфер строки `line[256]` + флаг `overflow` (BUG-013.3).  
- `af_oled.cpp`: эхо `>` + посимвольная печать (UTF-8 парами),  
  статус `ПРД RTTY 1000Hz` через `rttytx_center_hz()`.  
  
### Подводные камни  
  
1. **Порядок байтов в `baudot_rus`** — `(второй_байт<<8)|первый_байт`,  
   не наоборот (BUG-013.2).  
2. **`encode_char` — только `uint8_t`**: `char` signed, байты ≥0x80  
   отрицательны — сравнения с 0xD0/0xD1 молча не сработают.  
3. **Полоса фильтра и `RTTYTX_AMP` связаны**: при смене полосы/тапов  
   проверять спектр на клиппинг (гармоники 2.7k/4.5k).  
4. **`rttytx_busy()` = очередь + слот + хвост** — авто-возврат в RX  
   не обрезает посылку только если busy покрывает всё это.  
5. **CPFSK-лепестки ±100–200 Гц** вокруг тонов — спектр самого FSK,  
   фильтром не убираются; это норма для RTTY.

## CHANGE-005: CW-передатчик — фильтрация, русская Морзе, статус  
  
**Статус:** внедрено (коммиты `27398a5`…`e4b71e2`).

- **Русская Морзе**: `CWTX_RUS` (UTF-8 → код), уникальные буквы

- **`cwtx_tone_hz()`** — обратный пересчёт NCO-шага с +0.5

  на `af_dsp_cw_on()` (была дублирующая `rtty_on`).  
- **DC-blocker на выходе `af_tx_rtty_fir_push`** — биквад  
  `d = y - x1 + (32510*y1)>>15`, срез ~25 Гц; чистит DC  
  ключевого тона для CW и RTTY одновременно.  
  
### Подводные камни  
  
1. **`CWTX_AMP` — только на выходе, не в LUT**: ослабленная  
   таблица теряет разрешение → шум модуляции («завороты» у  
   подножия). У RTTY можно в LUT — огибающей нет.  
2. **Пиковый gain каскада ~+12 дБ** (`norm=2/sum` дважды):  
   `CWTX_AMP`/`RTTYTX_AMP` выше ~14000 — проверять спектр на  
   гармоники и `clip` в stats.  
3. **Порядок байтов в `CWTX_RUS`** — `(второй<<8)|первый`,  
   как `baudot_rus`.  
4. **Остаток у 0 Гц** — энергия огибающей на скорости  
   ключевания, не баг; не давить дальше (сброс фазы NCO дал бы  
   щелчки, у RTTY сломал бы CPFSK).  
5. **`cwtx_send` пишет `cwtx_text[n]='\0'`** — без этого `c2`  
   читает мусор за концом строки при тексте на `0xD0`.

## CHANGE-006: CW-сообщения, ключ, маяк, двухтональник, 3-полосный EQ  
  
**Статус:** внедрено и проверено на железе (коммиты `c3bb41e`,  
`bcb905c`, `83f25a0`, `419269b`, `45e3049`, `8805735`, `87f0c68`,  
`163939c`, `5afe565`, `f9816d6`, `5a6f1c1`, `9b07398`).  
  
### 1. Селектор сообщений GP13/GP28  
  
`af_gpio_msg_sel()` — 2-битный код (LOW=1) → 0..3. Выбирает слот  
магнитофона/строку CW.TXT для GP10.  
  
### 2. CW.TXT — 4 строки вызовов во flash и на диске  
  
- Хранение: блок по смещению 0x800 в секторе банков, свой  
  magic 'CW'+ver+crc — версию `AF_STORE_VER` не меняет.  
  `af_store_cw_init` читается безусловно в `af_store_init`  
  (при чужом секторе — обнуление по crc).  
- `af_cw_msgs[4][64]`: пустая строка = голосовой слот RECn,  
  непустая = CW-посылка. `af_store_cw_save` — то же flash-окно,  
  что `af_store_save` (park/mute/125МГц/IRQ-off).  
- MSC: файл CW.TXT на LBA 28 (1 кластер), рендер в `af_fm_sync`,  
  парсер записи с ПК по дебаунсу → `af_store_cw_save`.  
- CLI: `cw msg <1..4> <текст>` (пустой текст = голосовой слот),  
  `cw msgs`.  
  
### 3. Привязка GP10 к селектору  
  
`apply_play`: `idx = af_gpio_msg_sel()`; `af_cw_msgs[idx]` непустая →  
`af_dsp_cwtx_start` + PTT на GP8; пустая → голосовой слот.  
Добиватель ждёт `!af_dsp_cwtx_busy()` — PTT держится до конца  
посылки + послесвечение огибающей.  
  
### 4. Ямбический ключ GP11/GP12  
  
- `cw key off|on|iambic_a|iambic_b|straight` → `af_gpio_key_mode`.  
- Ручной режим cwtx: `cwtx_manual_begin/feed/key_down/key_up/end` —  
  элементы идут через ту же огибающую и FIR, что текстовые посылки.  
- `cwtx_el_rem_free()` — элемент доигран, можно feed следующего.  
- Mode B: память педалей не сбрасывается → дополнительный  
  противоположный элемент; Mode A сбрасывает обе.  
- `key_tx_on` проверяет `cwtx_busy()` — ключ не перебивает  
  текстовую посылку/маяк.  
- WPM общий с `cw txwpm`. Самоконтроль — тон в TX-тракте.  
  
### 5. CW-маяк  
  
`cw beacon <period_s 5..3600> <текст>` / `cw beacon off`.  
Таймер в `af_gpio_ctl_poll`: посылка по `af_dsp_cwtx_start` при  
свободном тракте (`!cwtx_busy && !rec && !key_tx`), занят →  
откладывание 0.5–1 с. PTT на время посылки, авто-возврат в RX.  
Текст не персистентен — после ребута маяк выключен.  
  
### 6. Двухтональный генератор (IMD-тест)  
  
- `src/modes/tt_gen.cpp`: два NCO с линейной интерполяцией LUT 256,  
  сумма ~0.4 FS, кламп частот в полосу TT-FIR.  
- Свой каскад FIR 400–3200 (`af_tx_tt_fir_push`) — существующий  
  700–1400 срезал бы тон 1900 и IMD3 на 3100.  
- Ветка в TX-мультиплексоре `af_dsp.cpp` между CW и RTTY;  
  взаимоисключение через `af_dsp_tt_start`.  
- CLI `tt on [f1 f2]|off` (дефолт 700/1900), статус `ПРД TT` на OLED.  
- Проверено: спуры −85..−95 дБ, `clip=0`, IMD3 на 3100 не виден.  
  
### 7. 3-полосный EQ (RX + TX)  
  
- Топология: low-shelf / peaking / high-shelf biquad каскадно,  
  коэффициенты float→fixed на Core 0 (`eq_design`, RBJ cookbook).  
- RX: `rxeq_push` после АРУ/полок, до выхода. TX: `txeq_push`  
  после `tx_pre`, до АРУ/компрессора.  
- Параметры: gain −120..+120 (дБx10, 0=off) + частота на полосу;  
  12 записей в `AF_PARAMS` (`rxeq lo|mid|hi`, `rxeq lo f`…, `txeq …`).  
- `af_bank_t` +12 полей, `AF_STORE_VER` 10→11 — старые банки  
  форматируются при старте.  
- Проверено: `rxeq mid 60` → `save 1` → ребут → `load 1` — на месте.  
  
### 8. Слоты магнитофона 7→4  
  
- `AF_REC_SLOTS 4`, `AF_FM_WAV_FILES 4` — диск показывает  
  REC1..REC4.WAV, таблицы имён в `dir_track`/`fm_build_dir` сокращены.  
- `rec_bank()` = `af_gpio_msg_sel()+1` — слот по селектору,  
  не по банку.  
- Хвост flash ~428 КБ не адресуется — TODO (см. TODO.md).  
  
### Подводные камни  
  
1. **`strtok(NULL, "")`** — трюк «весь остаток строки» для  
   `cw msg`/`cw tx`/`cw beacon`; работает на newlib, но хрупкий.  
2. **Парсер CW.TXT сжимает пустые строки** — «слот 2 пуст, слот 3  
   текст» через редактор не выразить (строки сдвинутся); через  
   `cw msg N` — можно.  
3. **`cw abort` не останавливает маяк** — обрывает текущую посылку,  
   следующая уйдёт по таймеру; полная остановка — `cw beacon off`.  
4. **Двойной возврат в RX после CW**: `cwtx_started` в `loop()` и  
   финишер GPIO оба отпускают TX — идемпотентно, но в логе две строки.  
5. **`key_straight_down` взводится до проверки `key_tx_on`** — при  
   занятом PTT состояние разъедется с педалью; безвредно.  
6. **EQ при gain=0 байпасится по `db_x10`** — коэффициенты не  
   пересчитываются; при смене частоты на выключенной полосе дизайн  
   откладывается до включения.

## CHANGE-007: Голосовой маяк `vbcn` (коммит `9577c52`)  
  
**Статус:** внедрено.  
  
### Что добавлено  
  
- **Команда `vbcn <period_s 5..3600> on|off`** — циклическое  
  воспроизведение голосового слота текущего банка  
  (`af_gpio_last_bank()`). Пустой слот → клип-заглушка `voice_14`  
  (ветка `slot_len == 0` в `af_rec_play`, отдельной обработки нет).  
  Сокращения `vbcn off` / `vbcn 0` — без периода.  
- **Период от конца воспроизведения**: флаг `vbcn_playing` держится,  
  пока `af_rec_is_playing()`; пауза `vbcn_period` стартует после  
  отпускания. Для CW-маяка период — от старта посылки (короткая  
  посылка), для голоса — от конца (клип до ~7.8 с).  
- **PTT/TX** поднимается через `af_gpio_ptt_tx_on()` перед  
  `af_rec_play()`; отпускает существующий добиватель  
  `sw_ptt_active && !af_rec_is_playing()` — дублировать не нужно.  
- **Взаимоисключение с CW-маяком**: `af_gpio_beacon_set` гасит  
  `vbcn_on`, `af_gpio_vbcn_set` гасит `beacon_on` — с логом  
  `[VBCN] off (cw beacon on)` / `[BEACON] off (vbcn on)`.  
- **Диагностика**: `# vbcn: playing bank N` при каждом старте,  
  `R|vbcn|0|1` в `state dump`, строка в `cli_help`.  
  
### Подводные камни  
  
1. **`af_gpio_ptt_tx_on() && af_rec_play()`** — обе функции должны  
   возвращать `bool`; при неудаче PTT возвращается через  
   `af_gpio_ptt_tx_off()` (иначе PTT завис бы поднятым).  
2. **`vbcn off` во время воспроизведения** — клип доиграет до конца  
   (PTT отпустит общий добиватель), мгновенной остановки нет.  
3. **Проверка занятости** включает `af_rec_is_recording()` — маяк  
   не перебивает идущую запись; при занятом тракте откладывание  
   0.5–1 с, как у CW-маяка.  
4. **Слот = `af_gpio_last_bank()`** — последний активный банк  
   (пины GP2..GP4 или `load N`), а не `rec_bank()` (селектор  
   GP13/GP28). Разные источники — осознанно: маяк привязан к банку,  
   кнопка GP10 — к селектору сообщений.
