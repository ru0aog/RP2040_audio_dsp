## Трёхполосный эквалайзер на приём (RX)  
  
Ввести в RX-тракт 3-полосный эквалайзер на Biquad IIR (БИХ),  
встающий ДО компрессора и клиппера — чтобы EQ формировал спектр  
до нелинейных стадий, а не после (иначе компрессор/клиппер  
«съедят» поднятые полосы и добавят гармоники).  
  
- Топология: 3 полосы — НЧ (low-shelf), СЧ (peaking), ВЧ (high-shelf),  
  каждая — один biquad (2-го порядка IIR), каскадно.  
- Параметры: частоты срезов/центра и gain каждой полосы — через  
  CLI-таблицу (PT_X100/PT_GAIN), по аналогии с tx-эквалайзером.  
- Целочисленная реализация на Core 1, коэффициенты Q31/Q15,  
  пересчёт — на Core 0 (float → fixed).  
- Место в цепочке: после полосового FIR/нотчей, до АРУ/компрессора.  
- Нагрузка: 3 biquad × ~5 MAC = ~15 MAC/отсчёт — копейки на Core 1.  
- Проверка: спектр на шум/станцию — подъём/завал полос без  
  гармоник; `clip` в stats не растёт.  

## Телеграфный ключ (CW keyer) с огибающей и самоконтролем  
  
Ручная передача Морзе с физического ключа (GPIO-вход), тон  
формируется через существующий `cwtx_sample` — та же  
raised-cosine огибающая и полосовой FIR 700–1400, что у  
`cw tx`.  
  
- Вход: GPIO с подтяжкой, антидребезг ~5 мс; прямой ключ  
  (straight key) и/или ямбический ключ (paddle, dit/dah  
  автоматика по `cw wpm`).  
- Огибающая: `CWTX_RISE_MS` raised-cosine на фронте/спаде —  
  без щелчков ключевания, как у текстовой посылки.  
- Самоконтроль (sidetone): тон 1000 Гц в монитор (USB/PWM)  
  во время нажатия — оператор слышит свою передачу.  
- Тракт: тот же путь, что `cwtx_sample` → `af_tx_rtty_fir_push`  
  → выход; `CWTX_AMP` и DC-blocker уже на месте.  
- Статус: `ПРД CW 1000Hz` на OLED во время работы ключом,  
  авто-возврат в RX после отпускания + таймаут (~1 с).  
- CLI: `cw key on|off`, `cw key mode straight|iambic`,  
  `cw key gpio <pin>`.  
- Взаимоисключение с `cw tx`/`rtty tx` через busy-проверки.  

## Стационарный 3-полосный эквалайзер (TX и RX)  
  
Параметрический EQ на biquad IIR — компенсация АЧХ микрофона/  
гарнитуры и тембра до динамической обработки. Дополняет  
существующий адаптивный эмфазис (tx_presence): стационарный  
EQ выравнивает базовый спектр, эмфазис подстраивается под  
текущую энергетику сигнала.  
  
- Топология: 3 полосы — НЧ (low-shelf), СЧ (peaking),  
  ВЧ (high-shelf), каждая — один biquad, каскадно.  
- TX: после tx_pre (полосовой FIR), до АРУ/компрессора —  
  чтобы EQ формировал спектр до нелинейных стадий.  
- RX: после АРУ, до выхода — та же структура, свои  
  коэффициенты.  
- Коэффициенты: float-расчёт на Core 0 (RBJ cookbook),  
  хранение Q31/Q15, пересчёт по CLI.  
- CLI: `eq tx lo|mid|hi <freq> <gain_dB> [Q]`,  
  `eq rx ...`, `eq on|off`, отображение в `params`.  
- Целочисленный biquad на Core 1: int64-аккумулятор  
  (как tx_presence — защита от wrap на пиках), ~5 MAC  
  на полосу, итого ~15 MAC/отсчёт — копейки.  
- Биквад работает всегда (как tx_presence): при gain=0  
  выход = вход, иначе при включении состояния x1/y1  
  устарели → щелчок.  
- Проверка: спектр на шум/речь — подъём/завал полос без  
  гармоник; `clip` в stats не растёт.  
  
## Телеграфный ключ / CW Keyer (расширение)  
  
Развитие пункта «Телеграфный ключ» до полноценного keyer:  
  
- Ямбический режим (Iambic Mode A/B): опрос двух GPIO  
  (dit/dah paddle), программный антидребезг ~5 мс,  
  автоматика элементов по `cw wpm`, регулировка Weight  
  (соотношение длительностей).  
- Прямой ключ (straight) — тот же вход, без автоматики.  
- Огибающая и тракт — готовые: `cwtx_sample` +  
  raised-cosine `CWTX_RISE_MS` + FIR 700–1400 +  
  `CWTX_AMP` + DC-blocker.  
- Самоконтроль (sidetone): тон 1000 Гц в монитор  
  (USB/PWM) во время нажатия.  
- CW Reader (опционально): декодирование собственной  
  передачи в текст на OLED — тайминги элементов уже  
  есть в keyer-автомате.  
- CLI: `cw key on|off`, `cw key mode straight|iam-a|iam-b`,  
  `cw key gpio <dit> <dah>`, `cw key weight <x100>`.  
- Взаимоисключение с `cw tx`/`rtty tx` через busy.  
  
## ADIF-логгер во Flash и на USB-диск  
  
Журнал QSO/наблюдений в формате ADIF: запись во flash  
(кольцевой буфер в свободных секторах) и экспорт на  
виртуальный USB-диск (af_fm MSC) как LOG.ADI.  
  
- Формат записи: <CALL> <QSO_DATE> <TIME_ON> <FREQ>  
  <MODE> <RST_SENT> <RST_RCVD> <EOR> — минимальный  
  ADIF, читается любым логгером.  
- Хранение: кольцевой буфер во flash (как REC-слоты),  
  примонтированный файл LOG.ADI на MSC-диске —  
  синтез секторов на лету, как REC*.WAV.  
- Источник времени: нет RTC — либо `log time <ISO>`  
  вручную, либо uptime + смещение, либо без даты  
  (поля опциональны в ADIF).  
- CLI: `log add <call> [rst]`, `log list`, `log clr`,  
  `log time <YYYY-MM-DD HH:MM>`.  
- FREQ/MODE подставлять автоматически из текущего  
  состояния приёмника.  

## CW-маяк с автоповтором (аварийная метка)  
  
Циклическая передача текста по таймеру — «подать сигнал из  
леса». RBN-скиммеры ловят CQ автоматически, синхронизация  
не нужна, дрейф гетеродина не критичен.  
  
- `cw beacon <text> <period_s>` — посылка каждые N секунд,  
  `cw beacon off` — стоп. Автоповтор через cwtx_send по  
  таймеру на Core 0 (~20 строк).  
- Тракт готов полностью: cwtx_sample → FIR 700–1400 →  
  DC-blocker → выход.  
- Статус `ПРД CW 1000Hz`, авто-возврат в RX между посылками  
  (или удержание TX — решить по PTT-схеме).  
  
## WSPR TX (ручной/отложенный старт)  
  
4-FSK, 1.4648 бод, шаг тонов 1.4648 Гц, 162 символа,  
~110.6 с. Сеть wsprnet.org — посылка видна в логах на  
«большой земле» даже при -28 дБ под шумом.  
  
- Кодирование на Core 0: упаковка позывной(28)+локатор(15)+  
  мощность(7) = 50 бит, свёртка K=32 r=1/2, интерливинг,  
  синхровектор — ~300 строк, считается один раз, CPU  
  избыточен.  
- Передача: клон rttytx-автомата с 4-шаговым NCO  
  (разрешение ~3.6 мГц — шаг 1.4648 Гц точный).  
- Базовая частота внутри полосы FIR 700–1400 (например,  
  1000 Гц + 4 тона вверх) — фильтр и DC-blocker уже есть.  
- Синхронизация: слоты по чётным минутам UTC, допуск  
  ~±1–2 с. Без RTC — `wspr tx at <сек>` отложенный старт:  
  оператор ждёт чётную минуту по внешним часам, вводит  
  обратный отсчёт.  
- Требование к опоре: дрейф < ~4 Гц за 110 с. Si5351 с  
  кварцем — достаточно при прогретом аппарате; на морозе  
  первые минуты дрейф может съесть допуск → задержка  
  старта/индикация «прогрев» на OLED.  
- CLI: `wspr tx <call> <grid> <dbm> [at <sec>]`,  
  `wspr abort`.  
  
## FT8 TX (ручной/отложенный старт)  
  
8-FSK GMSK, 6.25 бод, шаг 6.25 Гц, 79 символов, 15 с.  
Сеть pskreporter.info — больше приёмников, чем у WSPR;  
посылка короче → за 2 минуты можно выпустить 4 посылки  
в разные слоты (выше шанс при ручном старте).  
  
- Кодирование на Core 0: упаковка 77 бит (стандартное  
  сообщение CQ/CALL GRID), CRC14, LDPC(174,91) по  
  генераторной матрице ~1 КБ констант — XOR-операции,  
  миллисекунды на RP2040. Ориентир — ft8_lib (MIT).  
- Передача: клон rttytx с 8-шаговым NCO + гауссово  
  сглаживание переходов (GMSK) — иначе лепестки.  
- Полоса ~50 Гц — в FIR 700–1400 помещается с запасом.  
- Синхронизация: слоты кратны 15 с UTC, допуск ~±1 с —  
  жёстче, чем у WSPR. Без RTC — `ft8 tx at <сек>`.  
- Чувствительность ~-21 дБ (WSPR -28) — чуть хуже под  
  шумом, но сеть больше.  
- CLI: `ft8 tx <msg|call grid> [at <sec>]`, `ft8 abort`.  
  
## RTC-модуль для синхронизации слотов (DS3231)  
  
Единственный блокер WSPR/FT8/ADIF-лога — отсутствие  
энергонезависимых часов. Решение — I2C RTC.  
  
- DS3231 (TCXO, ±2 ppm ≈ ±1 мин/год, стабилен на морозе) —  
  НЕ DS1307 (±20 ppm ≈ ±1.7 с/сутки, за неделю уйдёт за  
  допуски слотов).  
- I2C, батарейка CR2032 — ход годами после одной установки.  
- CLI: `rtc` (показать), `rtc set <YYYY-MM-DD HH:MM:SS>`.  
- С RTC: `wspr tx`/`ft8 tx` стартуют автоматически в  
  ближайший слот с обратным отсчётом на OLED; ADIF-лог  
  пишет реальное время.  
- Альтернатива без железа: синхронизация по сигналам  
  точного времени (RWM 4.996/9.996/14.996 МГц) — красиво,  
  но дорого по коду и ненадёжно в поле; отложено.  

## Хвост flash после сокращения слотов магнитофона 7→4  
  
Регион `AF_REC_FLASH_OFF..0x1FDFFF` размечен на 7 слотов, используются  
4 (`AF_REC_SLOTS=4`). Хвост `0x193000..0x1FDFFF` (~428 КБ) не  
адресуется — `fmap` показывает его как `rec-slot(empty)`.  
  
- Вариант А: оставить — безвредно, `banks @0x1FF000` не пересекается.  
- Вариант Б: сократить `AF_REC_FLASH_LEN` до `4*AF_REC_SLOT_SIZE` —  
  хвост станет `free`, можно отдать под ADIF-лог/WSPR/длинные записи.  
- При сокращении проверить `af_rec_erase_all` — стирает весь  
  `AF_REC_FLASH_LEN`, границы пересчитаются сами.

## Хвост flash после переразметки слотов 4×224 КБ — ЗАКРЫТО  
  
Слоты расширены до 224 КБ (`0x11E000..0x1FDFFF`, 4×224 КБ = 896 КБ) —  
хвоста нет, вся область занята. Свободная зона — только  
`0x0FB000..0x11DFFF` (~140 КБ) между прошивкой и rec-slot.  

## Аплоад WAV >29 с — потоковая запись во flash  
  
Сейчас аплоад ограничен ram_buf (~29 с): инкрементальный  
ADPCM-encode в `ul_push` пишет нибблы в RAM, коммит — одним  
flash-окном. Для файлов длиннее — потоковая запись: pre-erase  
слота + инкрементальный `flash_range_program` по мере наполнения  
(окна посреди аплоада, ~45 мс каждое — хост терпит, MSC-таймауты  
секундные). Отдельная задача.
